*clay.txt*                clay.nvim — Grayscale and Clay for Neovim

Starting with v0.2.0, the theme is named clay.nvim. When upgrading from v0.1.0,
replace the claude module/colorscheme/lualine theme with clay, the Claude
highlight prefix with Clay, and the CLAUDE_ environment prefix with CLAY_.

==============================================================================
SETUP                                                          *clay-setup*

Add this repository to 'runtimepath' or install it with a plugin manager.
Requires Neovim 0.10.4+ and a true-color terminal.
>
    lua require('clay').setup({ accent = 'restrained' })
    colorscheme clay
<
setup() is optional. Each call replaces configuration using the defaults below.
Run :colorscheme clay again to apply changed options.

VERSIONING                                                 *clay-versioning*

Releases use annotated Git tags named vMAJOR.MINOR.PATCH. See CHANGELOG.md for
release notes and RELEASING.md for compatibility rules and release steps.
During 0.x development, fixes increment the patch version; new features and
breaking changes increment the minor version. Breaking and major visual changes
are documented explicitly. Neovim version requirements are separate from the
theme's release version. Local directory installations use the current checkout.

OPTIONS                                                      *clay-options*

accent              'restrained'  'minimal', 'restrained', or 'expressive'
transparent         true          Transparent editor and sidebar backgrounds
italic_comments     true          Italic comments
bold_keywords       false         Bold keywords
terminal_colors     true          Set the built-in terminal ANSI palette
palette             {}            Override named #RRGGBB colors
overrides           {}            Highlight table or function(colors, options)

Minimal accents only the UI. Restrained also accents function definitions.
Expressive also accents function calls. Definitions require Tree-sitter or LSP
declaration/definition modifiers; regex syntax uses neutral Function highlights
unless accent is 'expressive'.

The grayscale hierarchy is inspired by lackluster.nvim. Variables use #cccccc,
members and types use #aaaaaa, and keywords/calls/strings use #8e8e8e. Comments
and punctuation use #7a7a7a. Keywords are not bold by default. Clay (#d97757)
remains the accent for function definitions and UI focus in restrained mode.

Transparency is enabled by default. Set transparent=false for a solid #111315
editor background (RGB 17, 19, 21) and solid sidebar backgrounds. The actual
opacity is controlled by your terminal or GUI.
Transparent mode retains opaque popups, status bars, and selections.
Float and popup borders share the float background, so 'winborder' and
'pumborder' (Neovim 0.12) set to "solid" read as padding without extra setup.
Transparent window backgrounds set blend=0, so floats that reuse them with
'winblend' (such as noice's mini view) do not show the text beneath. The theme
sets 'background' to dark and enables 'termguicolors'. It does not change layout,
diagnostic settings, 'guicursor', or install/configure other plugins.

Terminal colors are grayscale except yellow/bright yellow, which use Clay.
terminal_colors=false leaves the existing palette untouched (does not restore a
previous palette).

Palette keys: bg, sidebar, float, cursorline, selection, statusline, border,
float_border, fg, bright, secondary, muted, subtle, comment, gutter, clay,
diff_add, diff_delete.

Override entries replace complete highlights, including links. An empty table
clears a highlight. The callback must return a highlight table.
>
    require('clay').setup({
      overrides = function(c)
        return { Comment = { fg = c.secondary } }
      end,
    })
<
get_palette() and get_options() return copies of the active configuration.
LuaLS annotations describe setup() as clay.Options; add the plugin to your
workspace library (lazydev.nvim does this) to complete option names.

Snacks covers picker, dashboard, and indent. mini.nvim covers statusline,
tabline, indentscope, jump, jump2d, starter, surround, trailspace, cursorword,
and diff. Plugins can add or override groups; file icons can use separate
third-party colors.

Rainbow delimiters use neutral shades for nesting. TODO, Git, and diagnostics
stay grayscale; active jump labels and interaction cues use Clay.

Disable nvim-scrollbar's own highlight generation to use the theme's groups:
>
    require('scrollbar').setup({ set_highlights = false })
<
Keep bufferline's options.themable=true (its default). Set highlight=true in
nvim-navic's setup to enable its icon/text highlights. The theme does not alter
these plugin settings.

Configure lualine after clay.setup():
>
    require('lualine').setup({ options = { theme = 'clay' } })
<
For a custom statusline: ClayMode is a Clay block, ClayAccent is Clay text,
and ClayMuted is secondary text. The theme does not set your statusline.

PREVIEW                                                       *clay-preview*

From the repository directory run `make preview`. This uses an isolated demo
configuration and works over SSH. Exit with :q!. Set CLAY_ACCENT=minimal or
CLAY_ACCENT=expressive to compare alternatives. Run `make test` for checks;
the tests require a Lua Tree-sitter parser.

Run `make preview-parsers` once for multilingual previews (Neovim 0.12+, current
nvim-treesitter, tree-sitter CLI 0.26.1+, cc, curl, tar required). Parsers and
queries are installed into .preview/site in the repository, not your personal
Neovim installation. CLAY_TREESITTER_DIR overrides the installer checkout;
its default is stdpath('data') .. '/lazy/nvim-treesitter'.

Use `make preview FILE=examples/demo.py` or :edit to change languages. The
statusline reports Tree-sitter or regex; :messages explains fallback errors.
Without a parser AND highlights query, function definitions may remain gray.
Run `make test-languages` to verify definition/call colors in nine languages.

CLAY_PREVIEW_RUNTIME accepts colon-separated runtime directories with parsers
and queries and overrides the preview cache path. Neovim older than 0.12 uses
bundled parsers unless this variable supplies compatible ones. No personal
configuration or plugin setup is loaded by the preview.

examples/demo.lua is the preview buffer. The same directory also has Rust, Go,
Python, TypeScript, C, C++, and Java samples. Open one from the preview
session with :edit. A matching Tree-sitter parser is used when installed.
