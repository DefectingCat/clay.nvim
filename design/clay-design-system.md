# Clay 设计规范

clay.nvim 的配色规则。移植到终端、其他编辑器、浏览器或任何界面时，以本文为准；`lua/clay/palette.lua` 是色值的唯一来源，本文的色板表与终端表由测试校验与其一致。

Clay 有暗色与亮色两个变体，共用同一套键名和语义映射，只有色值不同。

## 设计原则

1. **灰阶为底，Clay 点睛。** 层级靠亮度表达，而不是色相。除 Clay 和字符串的暖灰外，所有颜色都是 R = G = B 的中性灰。
2. **越重要对比越强。** 用户写的东西（变量、定义）与底色对比最强；语言结构（关键字、标点）退后；辅助信息（注释、行号、提示）最弱。
3. **Clay 只标记焦点。** 函数定义、光标、当前匹配、当前模式、选中项的提示符。同屏 Clay 越少越好；它不用于诊断、Git 或 Diff。
4. **状态靠亮度阶梯区分，不靠颜色。** 错误、警告、新增、删除都是灰，用不同亮度档位和符号区分。
5. **表面安静且中性。** 底色无色偏；离底色越远，层级越高：浮层一档，状态面再一档，选区和搜索最远。默认透明，让终端或宿主决定底色。
6. **相关状态必须可区分。** 会同时出现的两个状态（如搜索与选区、当前行与 Diff 行）不得共用同一颜色。

## 亮色变体的推导

亮色变体是暗色的镜像，而不是反相：

- **文字：** 每一档与亮色底色的 WCAG 对比度，等于暗色同一档与暗色底色的对比度。暗色里越亮，亮色里越深。
- **表面：** 每一档与底色的 L\* 距离与暗色相同，方向相反：暗色向亮处叠，亮色向深处叠。侧栏同样朝相反方向退一点。
- **字符串：** 保持与暗色相同的 Clay 色相和饱和度，只按对比度取亮度。
- **Clay：** 品牌色 `#d97757` 两个变体不变。代价是亮色下 Clay 文字与底色对比度只有 2.9，Clay 块上的底色文字同样是 2.9。
- **阴影：** 两个变体的阴影都比底色深，背景遮罩和浮窗阴影才能压暗下层。

键名按角色而非明暗命名：`bright` 指"最强强调"，在亮色变体中是最深的字。

## 语义映射

两个变体相同。

### 语法

| 元素                              | 颜色                                 | 样式       |
| --------------------------------- | ------------------------------------ | ---------- |
| 变量、模块、类型定义名            | `fg`                                 |            |
| 函数定义                          | 随点缀模式（见下）                   |            |
| 函数调用、构造调用                | 随点缀模式（见下）                   |            |
| 类型、常量、布尔、数字、成员/属性 | `secondary`                          |            |
| 字符串、字符、代码块              | `string`                             |            |
| 关键字、参数、内置变量、属性/注解 | `muted`                              | 默认不加粗 |
| 注释、文档字符串                  | `comment`                            | 默认斜体   |
| 标点、运算符                      | `subtle`                             |            |
| 内置函数                          | `subtle`；`expressive` 模式为 `clay` |            |
| 标题、TODO/FIXME                  | `bright`                             | 粗体       |
| 链接                              | `fg` 或 `secondary`                  | 下划线     |

### Diff 与 Git

| 状态     | 文字/符号     | 整行背景                                |
| -------- | ------------- | --------------------------------------- |
| 新增     | `bright`      | `diff_add`                              |
| 修改     | `secondary`   | `diff_change`                           |
| 删除     | `muted`       | `diff_delete`（填充符号用 `secondary`） |
| 行内变化 | `bright` 粗体 | `selection`                             |

| 级别  | 颜色        | 下划线             |
| ----- | ----------- | ------------------ |
| Error | `bright`    | 波浪线 `bright`    |

## 终端 ANSI 16 色

ANSI 颜色名是绝对颜色：两个变体中 black 都比 white 深。暗色里 white 就是正文色；亮色里 white 取浅灰，black 取正文色。

## 在 Neovim 中切换

主题跟随 `'background'`：`:set background=light` 切换到亮色，`dark` 切回暗色；Neovim 会自动重新加载主题，lualine 主题随之重新取色。Neovim 0.10+ 能根据终端底色自动设置 `'background'`。

`setup({ palette = ... })` 中，顶层颜色同时作用于两个变体；`dark`、`light` 子表只作用于对应变体，并优先于顶层颜色。

## 移植到其他软件

1. **先选变体，再按角色找颜色。** 目标软件的"keyword"“string”“selection”等槽位，对照语义映射表和对应变体的色板取色值；没有对应角色的槽位，取同类角色最接近的档位。
2. **只有 Clay 和 `string` 带色相。** 目标软件要求的红、绿、黄、蓝等彩色槽位，按 ANSI 表或诊断表映射回灰阶；不要另加彩色。
3. **Clay 控制在焦点上。** 光标、当前匹配、当前模式、选中项提示符、函数定义；其他地方用灰。
4. **表面只能远离底色叠加。** 浮层比底色远，选中比悬停远，搜索比选区远；当前行必须比浮窗底色离底色更远，否则浮窗里看不到当前行。
5. **透明底色时检查当前行。** 宿主底色接近 `cursorline` 时，改用离底色更远的当前行色。
6. **样式：** 注释斜体；关键字不加粗；粗体留给标题、错误、TODO、模式块和当前匹配。

### 移植检查

- [ ] 所有前景、背景、下划线颜色都是中性灰、Clay 或 `string` 暖灰
- [ ] 字符串与关键字、注释与标点颜色不同
- [ ] 新增、修改、删除三种 Diff/Git 状态颜色两两不同
- [ ] Warn、Info、Hint 颜色两两不同
- [ ] 搜索与选区背景不同；当前行与 Diff 行背景不同；当前行比浮窗底色离底色更远
- [ ] 正文对比度 ≥ 7，注释 ≥ 4；Clay 作为文字暗色 ≥ 4.5，亮色保持品牌色 `#d97757`
- [ ] 终端 red/green 与正文色不同；black 比 white 深
- [ ] 阴影和遮罩比底色深
